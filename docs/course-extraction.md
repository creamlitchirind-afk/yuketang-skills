# 雨课堂（长江）课程平台全量提取方法

> 面向"要复习/要搬运/要做自动化"的场景：把一门课（或一整学期的所有课）在雨课堂网页端读透，并落成可复习、可交接的本地文件。
> 全文基于 2026-11 对 13 个课程班级的实战，**已移除全部个人信息**（不含学号、姓名、成绩、班级 ID、教师姓名）。

## 0. 这套方法的边界

- 只做**只读**：不提交作业、不点"移出班级"、不点"报告老师"、不触发任何写接口。
- 只走**网页端**（浏览器），不依赖客户端、不抓包解密、不读凭据。
- 提取的"经验"是**结构与流程**，不搬运他人课程内容；公开时不含个人成绩与身份信息。

## 1. 先摸清三层结构，否则会一直在错的地方找东西

```
外层 v2 壳（左侧固定菜单：课程班级 / 资源库 / AI空间 / 返回旧版）
└─ 课程页 /v2/web/studentLog/{cid}?classroom_id={cid}&tab={tab}
   └─ 课程内容 iframe：/pro/lms/{course_sign}/{cid}/studycontent
```

三条经验：

1. **不是所有 tab 都在 iframe 里**。公告渲染在外层页；错题集、知识图谱是**独立路由**（`/v2/web/mistakeset/{cid}`、`/v2/web/knowledgegraph/...`）。进 iframe 找它们一定扑空。
2. 生产构建里 `#app` 上**没有** `__vue__`（整页计数为 0），靠 Vue 组件树取数的旧方法失效，只能走 DOM + 页面自己调的接口。
3. `course_sign` 从课程详情接口 `GET /v2/api/web/classrooms/{cid}?role={role}` 的 `data.course_sign` 取，用来拼 iframe 地址。

## 2. 一个接口拿到全部学习活动

```
GET /v2/api/web/logs/learn/{cid}?actype={n}&page=0&offset=50&sort=-1
```

**`actype` 是分区，`activity.type` 才是类型，两者不等价。**

| actype | 含义 | 常见 type |
|---|---|---|
| -1 | 全部 | 2 / 4 / 5 / 14 / 19 混合 |
| 2 | 课件 | 2 |
| 4 | 试卷 | 4 |
| 5 | 考试 | 5 |
| 14 | 线下课堂 | 14 |
| 15 | 线上学习 | 2 + 19 |
| 100 | 未完成 | 空数组即"无待办" |

字段口径：`count`=总页数、`view.depth`=已读页、`view.done`=是否读完、`end`=截止时间（毫秒）、`courseware_id`、`id`。

**最容易踩的一条**：判断"这门课有没有作业"要看 `type`，不能看 `actype=4/5` 是否为空 —— 大量课程把作业放在 `type 19`，只出现在 `actype=15` 和 `actype=-1` 里。

## 3. 作业有两套落地，先判类型再点

| type | 名称 | 落点 | 取分 |
|---|---|---|---|
| 4 | 试卷 / 考试 | `/v2/web/quizSummary/{cid}/{quiz_id}` → `studentQuiz` → `/v/quiz/quiz_info` | `quiz/personal_result?classroom_id=&quiz_id=` |
| 19 | 作业（含课前测） | `/ai-workspace/lms-graph/{cid}/exercise/{exercise_id}?node_id={nid}`，题面内嵌 `iframe /v2/web/iframe-exercise/{cid}/{exercise_id}?noLeftMenu=1&node_id=` | 只能读页面（见第 4 节） |

- 用 `type 19` 的 `activity.id` 去拼 `quizSummary` → 直接进 `/v2/web/errpage`。
- 拿课堂（`type 14`）的 `courseware_id` 去拼课件深链 → 同样 errpage。**两个 id 必须都来自 `actype=2`**。
- `studentLog` 里的 `activity.id` 不是 `exercise_id`，两者数字长度接近但不同，混用即报错。

### 拿 exercise_id 的稳办法

回课程内容页，在 iframe 里按**精确标题**点左侧叶子（`.leaf-detail .title` / `.leaf-title`），页面跳到 lms-graph，读 URL 里的 `/exercise/{id}?node_id={nid}`。

- 一次别排太多，**3 个一批**最稳；批量 10 个以上容易超时。
- 每批做完就关掉多余标签页（见第 8 节）。

## 4. 题面读不出来？是字形混淆，只能截图

作业正文注册了专用字体（`@font-face { font-family:"exam-data-decrypt-font" }`，字体文件由平台 CDN 提供）。DOM 文本被替换成**形近字**：屏幕上"信号"看着正常，`innerText` 读出来是"便强"。因此：

- `get_page_text()` / `innerText` 拿到的题干**不可引用**，粘进笔记等于毁题面；
- 正确做法：截图当图读；长题滚动后再截；
- **但判断题得分状态、正确答案、题号进度是明文**（`正确答案: A`、`本题得分`、`1/5 题`），可以用 JS 批量抓，拿来建答案表。

尝试过离线解码字体（`fonttools` 解析 cmap）：**882 条映射全部是 identity（cp → uniXXXX 且 XXXX == cp）**，说明平台是把"字形"画成了别的字，而不是替换码位，离线反解不可行。

### 截图稳定性

- 同一标签页第一次截图通常成功，第二次常报 `page viewport is unavailable` → 先 `resync()` 重新挂到前台标签，仍失败就开一个新标签页重截。
- 改过 `body.style.zoom` 的页面经常截不出来；要缩放着题，用新标签页重开最省事。
- 一屏一题最稳；`zoom≈0.65` 可读且能多放内容，代价是稳定性下降。

## 5. 课件与进度

- 权威进度：`/v2/api/web/cards/view_depth?classroom_id=&cards_id=` 的 `depth`，或 logs 里的 `view.depth`。
- **翻页本身不上报**，别指望"翻完就涨"。
- 课件正文：`/v2/api/web/cards/detlist/{cards_id}?classroom_id=`，`Slides[].Shapes` 里有文本 Html、图片和视频 `playurls` —— 这是**唯一能拿到课件原文**的接口，比 OCR 强。
- 深链：`/v2/web/studentCards/{cid}/{courseware_id}/{activity_id}/ppt`。
- 播放器是 swiper：`ArrowRight / ArrowLeft` 可翻页，`Space` 无效。
- 页内按钮：`打印课件` → `/web/print`；`查看学习数据` → 去掉 `/ppt` 的地址（学生端是空页，教师侧才有内容）；`报告老师` 是写操作，不要点。

## 6. 课堂、成绩单、其他 tab

- 课堂报告双入口：网页版 `student-lesson-report/{cid}/{lesson_id}/{card_id}`；更稳的是移动端 `/m/v2/lesson/student/{lessonId}/overview`。
- 上课快照：`/m/v2/lesson/student/{lessonId}/student-profile/{studentId}?tab=0`，给出进出课堂次数、停留时长、下课时间（出勤证据）。
- 成绩单 `?tab=student_school_report`：**详情一次渲染**，不要等"点模块出详情"，直接抓页面文本最省事。分数接口在另一套前缀（`schedule/score_statistic/...`、`score_setting/get_sku_evaluation_list_readonly/...`），缺平台要求的 `XTBZ` 头会一律返回 `XTBZ IS REQUIRED`。
- 我的归档：`.el-dialog.archiveDialog`，el-table 首行 4 格 = 班级名 / 学生数 / 活动状态 / 「移出」。**「移出」是写操作**。
- 「教学百宝箱」：网页端点它会把当前标签变成 `about:blank`（唤起客户端协议），换程序点击、原生 ref 点击都能复现，patch `window.open` 也捕获不到 URL。真正内容常在老师的第三方分享页（`html2web.com/p/xxxx`），部分带 6 位数字密码。

## 7. 得分显示的三层含义：别把"未批改"读成 0 分

同一个分数会在三个地方出现，口径不同：

1. **答题页顶部**：`1/1 题　1 未批改　1.主观题（100分）` —— "未批改"是老师还没批，系统对未批改主观题给 0。
2. **答卷区**：往下滚能看到自己的文字答案、插图、附件。**手写照片/对话截图是否交了，只能在这里核实**，不能由分数反推。
3. **成绩单**：汇总的是"已判分"的值，未批改即 0.000。

判读顺序：**先看答题页状态 → 再看答卷附件 → 最后才看成绩单**。
实战里就靠这个顺序纠正过一个错判：原本以为"手写照片没交导致 0 分"，复核后发现答卷里两页手写推导都在，页面状态是"未批改"，成绩单的 0.000 只是未批改显示值。

## 8. 标签页与进程卫生（每轮收尾必做）

每开一个标签页就多一份渲染进程与页面内存。一门课十几份作业如果"一份一个新标签"，很容易堆到十几个，症状是：截图失败、`resync()` 挂到别的标签、页面白屏、整体变慢。

工作方式：

1. **默认复用当前标签**（换地址而不是开新页）。
2. 需要并行对照时，最多留 **2–3 个**：一个列表页 / 一个目标内容页 / 一个备用。
3. 每做完一个对象就关：`switch_tab(target)` → `close_tab()`。
4. 收尾清点：列一遍标签页 URL，**同一 URL 出现两次就是可以关的**。
5. 只关本次自己开的、或与本任务重复的页面；用户自己的页面不动，不确定就保留。
6. 把"开过几个、清理几个、剩几个"记进台账，下次会话就知道浏览器现在的状态。

口诀：**能靠一个 URL 重开的就关；只有靠"页面内已点出的状态"才能复现的才留一个。**

## 9. 查重：不要重复抓已有的文件

一次完整提取前，先做本地盘点：

1. 按 `作业原件 / 复习记录 / 共享资料` 三类目录看已有文件，读该课 README、进度、台账。
2. **同名 + 同页数 / 同大小**才算重复。例：本地某章课件 PDF 是 59 页，平台该课件 `count=59` → 同一版，不再下载。
3. 只补"平台有、本地无"的缺口，并逐条写进台账：新增 / 修订 / 重复（明确写"不重复获取"）/ 仍缺。

附件下载：作业页里的 `a[href*=".pdf"]` 给的是对象存储直链，用浏览器下载能力取回，再按**原中文文件名**归档，不要改成 id 或时间戳。

## 10. 落盘结构（可直接照抄）

```
<课程>/
  README.md                     # 入口：平台标识 + 本轮产物链接
  期末复习_平台精读索引.md        # 基线 → 作业 → 练习 → 答案速查 → 材料 → 路线 → 缺口 → 来源
  资料获取与增量交接.md           # 台账：基线 / 已获取 / 缺口 / 增量 / 检索任务 / 接收记录
  平台截图证据/<日期>/           # 题面、状态、答卷、手写页
共享资料/<课程>/习题参考答案/      # 平台附件原件（保持原名）
```

索引文件建议固定这八节，换任何课都能直接套：**基线 → 作业（主）→ 练习（辅）→ 答案速查 → 材料清单 → 复习路线 → 缺口 → 来源核验**。

## 11. 常见坑速记

1. `type 19` 的 id 拼 `quizSummary` → errpage。
2. 课堂的 `courseware_id` 拼课件深链 → errpage。
3. 在复杂页面里按中文文本找元素可能返回 0 个节点，改按 class 或精确文本匹配。
4. `actype=100` 在"全读完"的课里必空，不能据此说"没作业"。
5. 公告在外层页；错题集、知识图谱是独立路由。
6. 平台部分接口缺 `XTBZ` 头一律报 `XTBZ IS REQUIRED`，页面内同步请求也带不上头，只能读已渲染页面。
7. 题面乱码 = 字体混淆，只能截图，不要引用文本。
8. 空班级 ≠ 没这门课：同课不同 `classroom_id` 的空壳班很常见，记录时要写明"以哪个 cid 为取数口径"，否则下次会对着空班白抓一遍。

## 12. 一次提取的检查清单

- [ ] 本地查重完成，确认无重复
- [ ] 课程标识（`course_sign`、考核方案、tab 清单）已取
- [ ] `logs/learn` 各 `actype` 都拉过，按 `type` 分类计数
- [ ] 作业拿到 id，且区分了 `type 4` 与 `type 19`
- [ ] 每份作业读了：任务要求、附件、我的答卷、状态（已提交/未批改/已批改）、截止
- [ ] 未提交或未批改的单元单独列出（这是最值钱的线索）
- [ ] 课件清单含 `已读/总页`，标出未读项
- [ ] 课堂清单含签到与得分
- [ ] 成绩单模块得分与班级对比已抄
- [ ] 附件已下载并按原名归档
- [ ] 索引 + 台账已写，缺口逐条列出
- [ ] 标签页已清理并记录数量
- [ ] 全程未触发任何写操作

## 13. 第三轮补充：客观题 vs 主观题、type 16、课件只有图

- **每章常并列四类叶子**：`图文`（type 16）/ `课件`（type 2）/ `作业`（type 19）/ `课堂`（type 14）。「图文」点开其实是有**客观题**的测验页，`id` 与 type 19 的 `leaf_id` 同量级。
- **客观题的答案与得分是明文**：`5/5 题`、`本题得分：2`、`正确答案： BD (少选得部分分)` 可直接 `innerText` 取；只有题干、选项被字形混淆。→ 客观题能批量建答案表，主观题不能。
- **已提交答卷是静态回放**：`.subject-item` = 5 个题号 + 1 个题面；点题号（含 mousedown/mouseup/click）、点上一题/下一题、按 `ArrowLeft` 都不改变题号显示；`window` 上没有题目全局对象。
- **`/mooc-api` 的 XTBZ 拿不到**：页面自身请求成功，页面内同步 XHR 返回 `XTBZ IS REQUIRED`；`network_requests()` 只有 url/method/status/request_id，不含请求头。想批量取全卷，得先 hook 请求头或找未提交状态的入口。
- **课件是「文字 + 图片」混合，按形态分流**：`cards/detlist/{courseware_id}?classroom_id=` 里，文本型形状取 `Slides[].Shapes[].Paragraphs[].Lines[].Texts[].Text`（纯文本、未混淆），图片型形状是 `URL → slide/...jpg`。实测 12 份课件：8 份有文字层、4 份纯图片；抽出的文字多为标题与要点，正文解释常在图里。纯图片的才需要打印导出 PDF 或 OCR。传 `activity.id` 会 `404001`，必须用 `courseware_id`。
- **`cards/view_depth` 的 cards_id 口径未定**：传 `activity.id` 得 `depth:0`，与 `logs/learn` 的 `view.depth`（21/21）不一致，暂以 `logs/learn` 为准。
