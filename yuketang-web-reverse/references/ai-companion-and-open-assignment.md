# AI 学伴对话计分与开放型作业写入（2026-11-23 实战）

本文件记录两类"非客观题"的实战路径：① AI 学伴模块的**对话次数区间计分**（可直接刷到满分）；② 开放型作业（主观题）的 **UEditor 富文本写入**（只写不提交）。两条都在 2026-11-23 真实页面跑通，含读回校验与分数判读。

---

## 1. AI 学伴：按「对话次数」区间计分

### 1.1 入口与面板结构

- 课程页内的学伴面板是一个 iframe，`src` 形如：
  `https://changjiang.yuketang.cn/ai-workspace/chatbot-window?chat_window_id=chatbot-small-<hash>`
  - 每个课程/每个窗口有独立 `chat_window_id`，不要跨课程复用同一个 iframe 地址。
- 面板是浮动小窗（右下角），消息气泡在上、输入框在下；操作前先把消息列表滚到最底，否则输入框可能被气泡遮住。
- 输入区常见为 `textarea` 或 `contenteditable`，发送按钮文案「发送」；两者都在 iframe 文档内，需经 `iframe.contentDocument` 定位，不要用主文档坐标点。

### 1.2 计分规则（页面内可查，勿凭经验猜）

- 规则表在面板 DOM 的 `.ai-score-rule-inner` 内，是一张两列表格。
- 实测口径（2026-11-23，信号与系统 25065612）：

| 对话次数 | 折算得分 |
|---|---|
| 0–24 次 | 0 分 |
| 25–49 次 | 25 分 |
| 50–99 次 | 50 分 |
| ≥100 次 | 100 分 |

- 该模块在成绩单里按 **10 分** 折算，即「AI学伴使用 x/10」；`x` 与上表的 0/25/50/100 一一对应（0/2.5/5/10）。

### 1.3 实操记录（可复用的推进节奏）

- 起点：82 次 → 模块 5.000/10（落在 50–99 档）。
- 补齐：连续发出约 22 条与课程内容相关的问题 → 101 次 → 模块 **10.000/10**，课程总分由 72.9 升到 77.9。
- 关键判据**只看页面显示的对话次数与成绩单模块分**，不看"我发了多少条"：
  1. 每次发送后读一次面板上的次数文本，确认 +1；
  2. 跨过 25 / 50 / 100 三个门槛后立刻去成绩单页核对模块分是否跳档；
  3. 已达 100 次即停，不必继续。
- 提问内容要与本课程相关（读课件/教材里的小节名即可生成一批），不要重复同一句，也不要空刷无意义字符。

### 1.4 坑

- **一次问答不一定只算 1 次**：计数口径是"对话轮次"，同一条消息内的追问可能不新增；以页面计数为准，别按发送条数估算。
- 面板缩放/页面 `zoom` 改动后，输入框可能移出可视区；写前把 `zoom` 复位到 1，或直接在 iframe 内用 JS 赋值+触发发送，避免坐标点击。
- 面板 iframe 网址里的 `chat_window_id` 会随会话变化，重新进入页面后要重新取 `src`，不要用上一轮的缓存地址。

## 2. 开放型作业（主观题）：UEditor 写入，只写不提交

### 2.1 页面与编辑器

- 作业原卷 iframe：`/v2/web/iframe-exercise/{classroom_id}/{exercise_id}?noLeftMenu=1&node_id={node_id}`
  - 外层主页面是 `/ai-workspace/lms-graph/{cid}/exercise/{eid}?node_id={nid}`，题目在**第一个 iframe** 里。
- 编辑器为百度 UEditor：外层 `.edui-editor`，正文在 **嵌套的第三层 iframe** `.edui-editor-iframeholder iframe`。
- **本页不暴露 `window.UE.instants`**：UEditor 官方 API（`UE.getEditor(...).setContent()`）在此不可用，按官方 API 写法会拿不到实例。

### 2.2 写入方法（实测可用）

```js
var f = document.querySelector('.edui-editor-iframeholder iframe');
var d = f.contentDocument || f.contentWindow.document;
d.body.focus();
d.execCommand('insertHTML', false, htmlChunk);   // 分段插入
```

- 长文按自然段切块（实测 1750 字左右切成 24 段插入最稳），每段 `<p>…</p>`，逐段 `insertHTML`。
- 写完读回校验：

```js
d.body.innerText.replace(/\s/g, '').length   // 与源文去空白字数一致即为写全
```

- 写入前若动过页面缩放，先 `document.body.style.zoom = '1'`，否则后续读回与滚动都会错位。

### 2.3 提交与分数判读（最容易误判的一环）

- **不代提交**：答案写入并读回校验后，交给用户在页面上自行核对、点「提交」。提交按钮在作业 iframe 内，不在主文档。
- 平台显示「已完成 0.000/5.000」**不等于交白卷**：主观题在批改前一律显示 0，属"待批改"。判读顺序：
  1. 先看状态是否为「已完成」；
  2. 已完成 + 0 分 = 待批改，不要重写重交；
  3. 只有状态仍是「未完成」或编辑器为空，才需要补写。
- 若用户坚持复核，隔一段时间再读成绩单；仍为 0 且状态已完成，则等教师批改，不做二次提交。

## 3. 与成绩读取的联动口径

- 成绩单页：`/v2/web/studentLog/{cid}?classroom_id={cid}&tab=student_school_report&university_id=3612&platform_id=3`
- 总分：正文 `成绩概况\s*([\d.]+)`
- 模块小计正则：`([\u4e00-\u9fa5A-Za-z]{2,8})\s*(\d+)个单元，共([\d.]+)分\s*个人得分：\s*([\d.]+)`
  - 常见模块名：作业、雨课堂课件（显示为"雨课堂课件"）、课堂、AI学伴使用、考试、视频、图文。
- AI学伴刷满、主观题批改后，都要重新读一次成绩单再对外报分数，不要拿刷分前的旧读数。

---

## 4. 边界

- 本文件的两条流程都属**写操作**：AI 学伴发问、作业写入，必须在当轮获得用户明确授权后才执行；作业**永不代提交**。
- 课堂签到、试卷提交、课程退出等一律不做。
- 遇安全核验/验证码，立即停手交用户本人处理。
